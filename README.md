# Work Hub — мобільний трекер щоденних задач

Простий застосунок для щоденних робочих задач, заточений під телефон. Працює
офлайн, встановлюється на домашній екран (PWA), не потребує сервера — усі дані
зберігаються локально в браузері.

## Можливості

- **Два розділи — «Робота» і «Особисте»** з перемикачем угорі: у кожного свої
  задачі, цілі та статистика (у «Особистого» — фіолетовий акцент). Обраний
  розділ запамʼятовується. Перемикати можна також **свайпом**: вліво —
  наступний розділ, вправо — попередній (працює на всіх трьох вкладках).
- **Екран задач** з групами `Сьогодні / Завтра / На тижні / Потім` (як у знайомих
  таск-менеджерах) та лічильником виконаного за день.
- **Класифікація задач:**
  - **складність** — легке / середнє / складне (колір чекбокса);
  - **повторення** — разові або регулярні (щодня, кожні N днів, по днях тижня,
    щомісяця — з календарною сіткою, де можна відмітити **кілька** чисел;
    31 означає останній день місяця, тобто 30, 29 або 28 у коротких). Виконана регулярна задача одразу переїжджає у групу свого
    наступного строку (щоденна — у «Завтра», щомісячна — у «Потім»), а не
    залишається перекресленою в «Сьогодні». Прогрес дня враховує й ті, що вже
    переїхали; випадкове натискання можна скасувати кнопкою в підказці.
  - **підзадачі-чекліст** можна додати будь-якій задачі.
- **Порядок у групі — за датою:** раніші задачі вище, прострочені спливають
  угору. Ручний порядок вирішує лише серед задач на один і той самий день.
- **Перетягування задач між днями**: довге натискання (≈0.3 с) «підіймає»
  задачу, далі тягнеш її в іншу групу або на нове місце в межах групи. У
  «Сьогодні»/«Завтра» дата задається групою, у «На тижні»/«Потім» — днем
  сусіда, біля якого впустив. Порожні дні показуються як мішені лише під час
  перетягування.
- **Статистика / трекер:** скільки виконано за день, тиждень, місяць, рік;
  середні значення за кожен період; серія днів поспіль; діаграми за 30 днів і
  12 місяців; розбивки за складністю, регулярні/разові та Робота vs Особисте.
- **Календар / архів** (кнопка вгорі праворуч): сітка місяця з крапками на днях,
  де щось заплановано або виконано; під нею — що саме стосується обраного дня
  (спершу заплановане, потім виконане). Виконані задачі зникають з головного
  екрана й лишаються в архіві за днем виконання. Відмічати можна лише
  сьогоднішній день, щоб не з'являлися хибні записи в статистиці.
- **Підтвердження виконання:** задача не зникає ривком — спершу видно
  поставлену галочку (з короткою анімацією), звучить двонотний сигнал, і лише
  за ~1 с рядок згасає. Звук можна вимкнути в налаштуваннях; згасання
  поважає системне «зменшити рух».
- **Події та нагадування** (окрема вкладка): важливі дати, які не треба
  виконувати — дні народження, свята, зустрічі. Мають плашку «Робота» /
  «Особисте» і видимі в обох розділах, бо про ДН треба памʼятати незалежно
  від режиму. Можна поставити **до двох нагадувань** (від «у момент події»
  до «за тиждень») і позначити подію як **щорічну** — тоді вона сама
  переходить на наступний рік.
  - Сповіщення у шторці телефона надсилає **системний Календар**: кнопка 📅
    віддає йому подію разом з нагадуваннями (файл `.ics` з `VALARM`, а для
    щорічних — `RRULE:FREQ=YEARLY`). Це єдиний спосіб без сервера, бо iOS
    «морозить» PWA і власний таймер застосунку у закритому стані не працює.
  - **Автоперенесення в Календар (підписка).** Записати подію прямо в
    Календар браузер не може — але Календар уміє сам ходити за `.ics` по
    посиланню. Застосунок публікує стрічку всіх подій у гілку `gh-pages`
    (Contents API, той самий токен, що й автокопія) і показує посилання
    `webcal://…`, на яке треба підписатися **один раз**: Налаштування →
    Календар → Облікові записи → Інше → Додати передплачений календар.
    Далі кожна нова подія доїжджає туди сама.
    - Файл лежить за шляхом `feed/<випадкові 18 hex>.ics` — адресу
      неможливо вгадати, але це **публічне** посилання.
    - Стрічка детермінована: `DTSTAMP` береться з самої події
      (`updatedAt`), а не з «зараз», інакше кожне заливання виглядало б
      як зміна й плодило порожні коміти. Задачі стрічку не чіпають.
    - Чого не обійти: момент оновлення обирає сам телефон (зазвичай раз на
      годину), підписаний календар доступний лише для читання, а перемикач
      «Вилучити сигнали» при підписці має лишатись **вимкненим** — інакше
      `VALARM` не спрацюють.
  - Поки застосунок відкритий, він показує нагадування й сам (через
    Notification API, якщо дозволено).
- **Цілі** з дедлайнами, кроками (milestones) і прогресом.
- **Нагадування** (час) і **нотатки** до задач.
- **Резервні копії:** копія вивантажується через системне «Поділитися»
  (на iPhone файл летить одразу у Файли/iCloud, а не губиться в «Завантаженнях»
  браузера); є запасний варіант звичайним завантаженням. Застосунок памʼятає
  дату останньої копії й показує банер, якщо копії немає або їй понад 14 днів.
  Відновлення приймає і новий формат з обгорткою, і старий «голий» JSON,
  перевіряє вміст файлу й питає підтвердження.

- **Автокопія на GitHub:** підключаєш приватний репозиторій і fine-grained
  токен — далі копія заливається сама, через ~5 с після кожної зміни.
  Кожне заливання — окремий коміт, тож історія версій виходить сама собою
  (є куди відкотитись, якщо в копію потрапить зіпсований стан). Токен
  зберігається окремим ключем `localStorage` і **не потрапляє** у файл копії.

### Захист даних

- `save()` зливає стан **поверх прочитаного** (`{...saved, ...state}`), тому
  відкат застосунку на стару збірку не витирає поля, яких вона не знає.
- Файл копії має обгортку `{_app, _version, _exportedAt, state}` — при
  відновленні видно, що це файл саме цього застосунку, і якої він давності.
- Автозаливання зупиняється, якщо задач раптово стало нуль або вдвічі менше,
  ніж у попередній копії — щоб зіпсований стан не затер хороший мовчки.
- Порівняння «чи щось змінилось» іде по стану, а не по файлу з обгорткою:
  інакше мітка `_exportedAt` робила б кожен виклик унікальним і плодила
  коміти з однаковим вмістом.

## Запуск

Це статичний сайт — жодного збирання не потрібно.

**Локально:**

```bash
# з кореня репозиторію
python3 -m http.server 8000
# відкрий на телефоні/у браузері: http://localhost:8000
```

Або просто відкрий `index.html` у браузері (service worker для офлайну
активується лише коли сайт відкрито через http/https).

**Розгортання (GitHub Pages):** увімкни Pages для гілки — сайт одразу доступний
за посиланням, яке можна відкрити на телефоні й «Додати на головний екран».

## Оновлення застосунку (для релізів)

Сайт роздається GitHub Pages з гілки `gh-pages`, тому будь-які зміни треба
залити і туди — інакше вони не поїдуть у продакшн.

**Обовʼязковий крок при кожному релізі:** підняти `VERSION` у `sw.js`
(`v3` → `v4` → …). Це змушує service worker перевстановитися, підтягнути свіжі
файли й прибрати старий кеш, а сторінка автоматично перезавантажиться на нову
версію. Перевірено: з бампом версії оновлення видно з **першого** відкриття
застосунку; без бампу — лише через кілька запусків.

Дані користувача (`localStorage`) при оновленні не зачіпаються.

**Важливо: `gh-pages` більше не можна перезаписувати силою.** Стрічка подій
для Календаря (`feed/*.ics`) живе лише в цій гілці — її туди пише сам
застосунок через API. `git branch -f gh-pages main` знищив би її, і підписка
в телефоні спорожніла б. Тому публікуємо злиттям:

```bash
# типовий реліз
#   1) підняти VERSION у sw.js
git commit -am "..."
git push origin main

# публікація: вливаємо main у gh-pages, не чіпаючи feed/
git checkout gh-pages && git merge --no-edit main
git push origin gh-pages && git checkout main
```

## Структура

```
index.html                 розмітка + підключення
assets/css/styles.css      мобільні стилі (світла/темна тема)
assets/js/store.js         дані, збереження (localStorage), бізнес-логіка
assets/js/gitsync.js       автокопія у приватний репозиторій GitHub
assets/js/calfeed.js       стрічка .ics для підписки системного Календаря
assets/js/app.js           інтерфейс: рендеринг, події, форми
manifest.webmanifest       PWA-маніфест
sw.js                      service worker (офлайн)
assets/icons/              іконки застосунку
```

Дані живуть у `localStorage` цього пристрою. Для перенесення на інший пристрій
скористайся експортом/імпортом у налаштуваннях (шестерня у бічному меню).
